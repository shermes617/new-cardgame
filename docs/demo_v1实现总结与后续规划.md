# 《裂隙远征》Demo v1 实现总结与后续规划

## 1. Demo v1 当前状态

Demo v1 已基本完成核心玩法原型，当前可以反复进行完整的 4v4 时间轴卡牌战斗：

```text
进入战斗
↓
玩家控制固定四人小队进行时间轴战斗
↓
胜利后从三张通用卡中选择一张加入牌组
↓
继承我方当前生命并进入下一场战斗
↓
失败后重新开始本次运行
```

当前版本的主要目标已经达成：

- 验证 4v4 时间轴卡牌战斗的基本可玩性。
- 验证共享手牌、共享能量和多角色行动选择。
- 验证蓄力、过载和速度形成的行动时间差异。
- 验证战斗奖励、牌组增长和连续战斗循环。

---

## 2. 当前实现的战斗界面

战斗界面由三个主要区域组成：

- 顶部：当前局内时间和未来事件时间轴。
- 中部：我方与敌方 4v4 战场。
- 底部：当前行动提示、抽牌堆、能量、手牌重置、手牌和弃牌堆。

站位顺序为：

```text
我方 4-3-2-1 | 敌方 1-2-3-4
```

我方 1 号位和敌方 1 号位最靠近战场中心。

玩家可以：

- 在同一时间有多个我方角色可行动时，选择本次优先行动的角色。
- 选择普通攻击或一张可用手牌。
- 根据卡牌规则选择合法目标。
- 取消当前行动选择。
- 使用手牌重置按钮更换手牌。

---

## 3. 时间轴与行动逻辑

战斗使用离散时间轴，不按传统固定回合推进。

系统会自动跳转到下一个事件时间，并按照事件优先级结算。

当前同时间事件顺序为：

```text
1. 我方技能发动
2. 敌方技能发动
3. 能量恢复与手牌重置刷新
4. 我方行动
5. 敌方行动
```

### 我方行动

- 四名我方角色首次行动时间均为 `0.0`。
- 同时间可行动角色由玩家决定行动顺序。
- 角色开始行动时，会先清空自己的现有护盾。
- 玩家选择行动后，系统创建技能发动事件与下一次行动事件。

### 敌方行动

- 敌人不会在 `0.0` 行动。
- 敌人第一次行动发生在自身行动间隔之后。
- 每次行动后，继续按照固定行动间隔安排下一次行动。
- 当前敌人使用固定的敌方普通攻击。

### 蓄力与过载

- 蓄力决定卡牌效果在哪个未来时间点发动。
- 过载决定角色在技能发动后多久可以再次行动。
- 下一次行动时间从技能发动时间开始计算，而不是从选择卡牌时开始计算。
- 我方角色速度会缩短实际过载时间，实际过载最低为 `1.0`。

## 4. 单位、伤害与生存规则

Demo v1 固定包含四名我方角色和四名敌人。

### 我方角色

- 亚瑟：前排输出。
- 贝琳：防御承伤。
- 克洛伊：快速输出。
- 莉雅：护盾与治疗。

### 敌人 AI

- 裂隙虫：随机选择存活我方目标。
- 藤蔓兽：攻击当前生命最低的我方角色。
- 潮汐蟹：优先攻击最靠前的存活我方角色。
- 遗迹骷髅：随机选择存活我方目标。

### 伤害与护盾

- 伤害优先扣除护盾，剩余伤害再扣除生命。
- 护盾可以叠加。
- 角色在自己的行动点开始时清空自身护盾。
- 行动过程中获得的新护盾会保留到下一次行动点。
- 生命降至 `0` 后单位死亡。
- 死亡单位未来的行动和技能事件会被取消。
- 蓄力中的卡牌因角色死亡而取消时，该卡牌会进入弃牌堆。

### 胜负规则

- 所有敌人死亡时战斗胜利。
- 所有我方角色死亡时战斗失败。
- 双方同时全灭时按失败处理。
- 战斗结束后清空事件队列并停止推进时间轴。

## 5. 普通攻击、能量与卡牌效果

### 普通攻击

普通攻击是每名我方角色始终可使用的固定行动：

- 不属于卡牌，不进入牌组。
- 不消耗能量。
- 对单体存活敌人造成 `100%` 力量伤害。
- 发动后立即恢复 `1` 点能量。
- 基础过载较长，用作能量不足时的保底行动。

### 能量系统

- 战斗初始能量为 `3`。
- 能量上限为 `10`。
- 每个整 `10` 时间点自动恢复 `1` 点能量。
- 能量不会超过上限。
- 能量补充卡会创建未来的延迟回能事件。

### 当前卡牌效果类型

系统已支持以下数据驱动效果：

- 单体伤害。
- 全体伤害。
- 单体护盾。
- 全体护盾。
- 治疗。
- 抽牌。
- 延迟获得能量。
- 根据实际生命伤害获得护盾。

当前初始牌组为：

```text
打击 ×5
防御 ×5
```

胜利奖励可以从十张通用卡中选择，包含快速攻击、蓄力攻击、范围攻击、防御、治疗、抽牌、延迟回能和铁斩波等效果。

## 6. 牌堆与手牌规则

### 基础规则

- 战斗开始时洗牌并抽取 `5` 张牌。
- 手牌上限为 `9` 张。
- 抽牌堆为空时，将当前弃牌堆打乱并转移到抽牌堆。
- 抽牌堆与弃牌堆总数不足时，抽完所有可抽卡牌后停止。
- 手牌已满时，新抽到的卡牌直接进入弃牌堆。

### 卡牌使用与弃置顺序

使用一张卡牌时：

```text
1. 检查能量与目标
2. 扣除能量
3. 从手牌移出卡牌
4. 创建技能发动事件
5. 卡牌效果发动
6. 效果全部结算后，卡牌进入弃牌堆
```

因此，抽牌战术发动时不会把自己回洗并重新抽到手中。

### 手牌重置

当前实际实现已经替代原设计文档中的“周期自动抽牌”和“手牌过期”：

- 手牌不会自动过期。
- 不会每隔固定时间自动抽牌。
- 玩家可以点击手牌重置按钮，弃掉全部当前手牌并抽取 `5` 张。
- 使用后按钮暂时不可用。
- 按钮在下一个整 `10` 时间点刷新。
- 如果恰好在整 `10` 时间点使用，则在下一个整 `10` 时间点刷新。
- 未使用时不会生成刷新事件，也不会累积使用次数。

## 7. 战斗奖励与连续战斗

胜利后会显示三张不同的通用卡奖励：

- 奖励按钮显示卡牌名称、费用和效果描述。
- 玩家选择其中一张加入当前运行的牌组。
- 未选择的奖励不会加入牌组。
- 选择完成后进入下一场固定战斗。

连续战斗规则：

- 继承我方角色当前生命。
- 继承当前运行牌组和已获得的奖励卡。
- 重置护盾、能量、手牌、牌堆状态、事件和敌方状态。
- 结算界面显示已完成战斗数和当前牌组数量。
- 失败后可以重置运行状态并重新开始。

## 8. 工程结构与数据驱动

当前工程按职责拆分主要模块：

### 数据与模型

- `GameDatabase`：集中加载并校验角色、敌人、卡牌、配置和初始牌组。
- `BattleState`：保存单场战斗状态。
- `GameRunState`：保存跨战斗的牌组、继承生命和已完成战斗数。
- `UnitState`、`CardData`、`HandCard`：保存对应运行时数据。

### 战斗规则

- `BattleFlow`：推进时间轴、处理行动点、敌人行动和胜负。
- `EventQueue`、`BattleEvent`：保存并排序未来事件。
- `ActionScheduler`：安排技能发动与下一次行动。
- `BattleResolver`：结算伤害、护盾、治疗、抽牌和能量效果。
- `DeckManager`：管理抽牌堆、手牌、弃牌堆和回洗。
- `EnergyManager`：管理能量获得、消耗和恢复事件。
- `HandResetManager`：管理手牌重置与刷新事件。
- `EnemyAI`：选择敌人行动目标。
- `RewardManager`：生成三选一卡牌奖励。

### UI

- `BattleSceneController`：连接战斗规则与界面。
- 独立 UI 场景负责时间轴、单位、卡牌、行动面板和结算面板。
- UI 只负责显示和接收操作，不直接计算伤害或修改核心规则。

### 外置数据与本地化

- 角色、敌人、卡牌、初始牌组和战斗配置使用 JSON。
- 正式界面文本、角色名称和卡牌描述使用中英文翻译 Key。
- 数据加载阶段会检查必要字段、ID、数值和资源引用。

## 10. 当前不足与暂未实现内容

Demo v1 已具备核心玩法循环，但仍属于机制原型。

当前主要不足：

- 行动、技能发动、受击、治疗、护盾和死亡缺少动画与视觉反馈。
- 时间轴事件只提供基础文本和图标信息。
- 当前敌人组合固定，重复战斗变化较少。
- 数值尚未经过系统试玩和平衡调整。
- 没有完整的战斗日志和伤害数字反馈。
- 没有主菜单、设置、教程、地图、存档和正式关卡流程。
- 当前连续战斗没有明确终点或最终目标。
- 原设计文档仍保留部分已经废弃的自动抽牌与手牌过期描述。

## 11. 下一阶段任务目标

下一阶段建议先进入“可试玩版本完善”，不要立即扩展大型局外系统。

### 优先级 1：战斗反馈与可读性

目标是让玩家能够清楚理解每次操作产生了什么结果。

- 增加伤害、治疗、护盾和能量变化反馈。
- 增加技能发动、受击和死亡表现。
- 突出当前行动角色、可选目标和已选择卡牌。
- 改善时间轴事件重叠时的可读性。
- 增加关键操作提示和错误原因提示。

### 优先级 2：试玩与数值平衡

目标是验证核心战斗是否有持续决策空间。

- 试玩不同角色使用同一张卡牌时的差异。
- 调整角色速度、敌人行动间隔和卡牌过载。
- 调整能量恢复、普通攻击回能和卡牌费用。
- 验证手牌重置的刷新周期是否合理。
- 检查治疗、防御和输出卡的使用价值。
- 记录并修复试玩中发现的规则边界问题。

### 优先级 3：战斗内容扩展

目标是在保持现有结构的前提下增加重复游玩的变化。

- 将敌人组合外置为战斗配置或遭遇数据。
- 增加不同敌人组合和战斗难度。
- 增加更明确的敌方行动意图显示。
- 增加新的卡牌效果、敌人行为和战斗规则。
- 设计一组有明确起点与终点的测试关卡。

### 优先级 4：Demo v1 之后的系统规划

在核心战斗经过试玩验证后，再规划：

- 地图与关卡路线。
- 局外成长与牌组管理。
- 角色招募和角色专属内容。
- 装备、藏品和其他长期成长系统。
- 存档、设置、教程和正式游戏流程。
