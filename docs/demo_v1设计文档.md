# 《裂隙远征》Demo v1 设计文档

面向从 0 开始理解项目的人，以及 Codex 开发执行使用。

---

## 0. Demo v1 的目标

本 Demo 的目标不是完成完整游戏，而是验证本游戏最核心的战斗与基础循环。

本游戏的核心是：

> 4v4 站位战斗 + 离散时间轴 + 卡牌行动 + 能量系统 + 角色属性影响卡牌效果。

Demo v1 需要实现一个最小可玩的战斗原型，并附带非常基础的战斗后奖励循环。

---

# 1. 游戏一句话介绍

《裂隙远征》是一款 PVE 战术卡牌游戏。

玩家控制 4 名角色，与敌方 4 名单位进行战斗。战斗不是传统回合制，而是基于“时间轴”推进。

角色使用卡牌后，不会立刻再次行动，而是根据卡牌的“过载时间”决定下一次行动时间。部分卡牌有“蓄力时间”，需要等待一段时间后才会发动。

# 3. Demo v1 的核心玩法循环

Demo v1 的基础流程为：

```text
进入战斗准备
↓
使用固定 4 人小队
↓
进入 4v4 战斗
↓
通过时间轴推进战斗
↓
玩家在角色行动点选择普通攻击或手牌
↓
敌方自动行动
↓
一方全灭后战斗结束
↓
胜利后获得三选一卡牌奖励
↓
卡牌加入牌组
↓
进入下一场测试战斗
```

Demo v1 不需要地图移动，只需要能连续测试多场战斗。

# 4. 核心概念说明

## 4.1 时间

战斗中使用“局内时间”。

规则：

```text
1 时间 = 1 小时
24 时间 = 局外 1 天
```

Demo v1 中可以先显示局内时间即可。

例如：

```text
当前时间：8.0
下一个事件时间：10.5
```

时间允许使用 1 位小数。

---

## 4.2 关键断点

时间轴不会每秒流动，而是自动跳到下一个关键断点。

关键断点包括：

```text
1. 我方技能发动
2. 敌方技能发动
3. 我方角色行动
4. 敌方角色行动
5. 抽牌事件
6. 能量恢复事件
7. 手牌过期事件
8. 延迟获得能量事件
```

系统每次找到时间轴上最近的事件时间，并跳转到该时间点进行结算。

---

## 4.3 同时间点结算顺序

如果同一时间点有多个事件，按照以下顺序结算：

```text
1. 我方技能发动
2. 敌方技能发动
3. 抽牌
4. 能量恢复
5. 我方行动
6. 敌方行动
7. 手牌过期
8. 其他延迟事件
```

注意：

如果某个单位在前面的结算中死亡，那么它后续尚未结算的行动或技能发动事件应取消。
如果我方角色可以在同一时间点行动，那么可以让玩家选择谁先行动。
敌人在从0开始计算的行动间隔后开始第一次行动，每次行动后也经过行动间隔开始下一次行动。

# 5. 战斗站位

## 5.1 站位结构

我方 4 个位置，敌方 4 个位置。

靠近中间的是 1 号位，越往后数字越大。

```text
我方4号位 我方3号位 我方2号位 我方1号位  敌方1号位 敌方2号位 敌方3号位 敌方4号位
```

Demo v1 中可以先不实现复杂位置限制。

所有攻击牌可以先允许攻击任意存活敌人。

所有防御和治疗牌可以先允许选择任意存活我方角色。

# 6. 角色属性

每个角色有 4 个基础属性：

```text
力量
意志
生命
速度
```

## 6.1 属性作用

### 力量

影响攻击卡牌伤害。

例如：

```text
100%力量伤害 = 使用者力量 × 1.0
150%力量伤害 = 使用者力量 × 1.5
```

---

### 意志

影响护盾和治疗。

例如：

```text
100%意志护盾 = 使用者意志 × 1.0
70%意志治疗 = 使用者意志 × 0.7
```

---

### 生命

决定最大生命值。

角色生命降为 0 时死亡。

---

### 速度

影响卡牌实际过载时间。

Demo v1 中，蓄力暂时不受速度影响。

过载计算公式：

```text
实际过载 = max(1.0, 基础过载 + 速度 × 过载速度修正)
```

结果四舍五入保留 1 位小数，并用于时间轴计算与显示。

例如：

```text
基础过载 = 4
过载速度修正 = -0.2
速度 = 4

实际过载 = 4 + 4 × (-0.2)
实际过载 = 3.2
```

普通攻击不是卡牌，不进入牌库，不占手牌。

## 普通攻击

```text

类型：固定行动
能量：0
蓄力：0

过载速度修正：-0.2
效果：
  对单体敌人造成100%力量伤害
```


# 12. 能量系统

## 12.1 能量上限

```text
能量上限 = 10
```

能量不能超过上限。

如果当前能量为 9，获得 2 点能量，则最终能量为 10。

---

## 12.2 初始能量

Demo v1 建议：

```text
战斗开始初始能量 = 3
```

---

## 12.3 自动回能

建议规则：

```text
每经过10局内时间，恢复1点能量
```

系统需要在时间轴中创建能量恢复事件。

例如：

```text
战斗开始时间 = 0
能量恢复事件：10、20、30、40……
```

---

## 12.4 普通攻击回能

我方角色使用普通攻击后：

```text
立即恢复1点能量
```

---

## 12.5 能量补给卡

“能量补给”不是立刻获得能量，而是创建一个延迟事件。

```text
使用时：
当前时间 + 6 创建一个获得2能量事件
```

例如：

```text
当前时间 = 5
使用能量补给
在时间11获得2点能量
```

# 13. 手牌系统

## 13.1 手牌上限

```text
手牌上限 = 9
```

如果抽牌时超过手牌上限，多余牌直接进入弃牌堆。

---

## 13.2 初始抽牌

Demo v1 建议：

```text
战斗开始抽5张牌
```

---

## 13.3 自动抽牌

建议规则：

```text
每经过5局内时间，抽1张牌
```

系统需要在时间轴中创建抽牌事件。

例如：

```text
战斗开始时间 = 0
抽牌事件：5、10、15、20……
```

---

## 13.4 手牌过期

每张手牌有保留时间。

规则：

```text
每张手牌保留7时间
```

当一张牌进入手牌时，记录：

```text
过期时间 = 当前时间 + 7
```

当到达过期时间，该牌进入弃牌堆。

如果过期时间与我方行动点相同，先允许我方行动，再处理手牌过期。

这由同时间点结算顺序保证。

---

## 13.5 抽牌堆与弃牌堆

战斗开始时：

```text
牌组洗牌形成抽牌堆
从抽牌堆抽5张
使用过的卡进入弃牌堆
过期的卡进入弃牌堆
抽牌堆为空时，将弃牌堆洗牌形成新的抽牌堆
```

# 14. 护盾系统

## 14.1 护盾可以叠加

角色获得护盾时，直接加到当前护盾上。

```text
当前护盾 = 当前护盾 + 新获得护盾
```

---

## 14.2 伤害优先扣护盾

当角色受到伤害时：

```text
先扣护盾
护盾不足时，剩余伤害扣生命
```

示例：

```text
生命：30
护盾：8
受到伤害：12

先扣8护盾
剩余4伤害扣生命

结果：
生命：26
护盾：0
```

---

## 14.3 行动前清空自身护盾

当一个角色到达自己的行动点时，在玩家选择行动之前，先清空该角色当前护盾。

注意：

```text
只清空当前行动角色的护盾
不清空全队护盾
```

流程：

```text
角色行动点开始
↓
清空该角色当前护盾
↓
玩家选择行动
↓
如果本次行动获得新护盾，新护盾会保留
↓
直到该角色下一次行动点开始前
```

设计意义：

```text
护盾保护的是“现在到目标下次行动前”的时间窗口。
```

---

# 15. 治疗系统

治疗直接恢复生命。

规则：

```text
治疗量 = 使用者意志 × 治疗倍率
```

治疗不能超过最大生命。

例如：

```text
莉雅意志 = 12
治愈之光 = 80%意志治疗

治疗量 = 12 × 0.8 = 9.6
```

Demo v1 四舍五入为 10。

建议生命、伤害、治疗都使用整数显示，计算后四舍五入为整数。

---

# 16. 伤害系统

## 16.1 单体伤害

```text
伤害 = 使用者力量 × 倍率
```

例如：

```text
亚瑟力量 = 12
打击 = 100%力量伤害

伤害 = 12
```

---

## 16.2 范围伤害

范围伤害作用于所有存活敌人。

例如：

```text
旋风斩：
对所有存活敌人造成80%力量伤害
```

如果亚瑟力量为 12：

```text
每个敌人受到 12 × 0.8 = 9.6 ≈ 10 伤害
```

---

# 17. 卡牌发动流程

当角色使用一张卡牌时：

```text
1. 检查能量是否足够
2. 检查目标是否合法
3. 扣除能量
4. 从手牌移除该卡
5. 计算技能发动时间
6. 创建技能发动事件
7. 计算角色下一次行动时间
8. 创建角色下一次行动事件
9. 卡牌进入弃牌堆
```

---

## 17.1 技能发动时间

```text
技能发动时间 = 当前时间 + 蓄力
```

Demo v1 中蓄力不受速度影响。

如果蓄力为 0，则技能在当前时间点的技能发动阶段结算。

实现上可以立即结算，也可以创建当前时间的技能发动事件，但要保证结算顺序正确。

---

## 17.2 下一次行动时间

```text
下一次行动时间 = 技能发动时间 + 实际过载
```

注意：

过载从技能发动后开始计算，而不是从选择技能后开始计算。

例如：

```text
当前时间 = 5
使用重击
蓄力 = 1
实际过载 = 4.2

技能发动时间 = 6
下一次行动时间 = 10.2
```

---

# 18. 角色行动流程

当我方角色到达行动点：

```text
1. 检查角色是否存活
2. 清空该角色当前护盾
3. 暂停时间轴
4. 玩家选择行动：
   - 普通攻击
   - 使用一张手牌
5. 玩家选择目标
6. 执行动作创建事件
7. 继续推进时间轴
```

---

# 19. 敌方行动流程

当敌方角色到达行动点：

```text
1. 检查敌人是否存活
2. 清空该敌人当前护盾
3. 自动选择敌方普通攻击
4. 自动选择目标
5. 创建技能发动事件
6. 创建下一次行动事件
7. 继续推进时间轴
```

Demo v1 敌方 AI 可以非常简单。

目标选择规则可以先用：

```text
随机选择一个存活我方角色
```

或者按敌人类型指定：

```text
裂隙虫：随机目标
藤蔓兽：生命最低目标
潮汐蟹：优先攻击前排
遗迹骷髅：随机目标
```

---

# 20. 战斗胜负

## 20.1 胜利条件

```text
所有敌方单位生命 <= 0
```

## 20.2 失败条件

```text
所有我方单位生命 <= 0
```

Demo v1 中，角色死亡后不再行动，相关未来事件取消。

---

# 21. 战斗奖励

战斗胜利后，显示三选一卡牌奖励。

规则：

```text
从通用卡池中随机抽取3张不同卡牌
玩家选择1张加入牌组
未选择的2张丢弃
```

Demo v1 可暂时不实现金币。

如果要实现金币，可以简单设定：

```text
每场胜利获得10金币
金币暂时只显示，不消费
```

# 24. 模块职责

## 24.1 battle_controller.gd

负责战斗总流程。

```text
开始战斗
推进时间轴
处理玩家行动
处理敌方行动
判断胜负
进入奖励界面
```

---

## 24.2 battle_state.gd

保存战斗当前状态。

```text
当前时间
我方单位列表
敌方单位列表
当前能量
抽牌堆
手牌
弃牌堆
事件队列
```

---

## 24.3 event_queue.gd

负责事件队列。

```text
添加事件
移除事件
获取下一个事件时间
获取同一时间点所有事件
按优先级排序事件
取消死亡单位未来事件
```

---

## 24.4 timeline_manager.gd

负责时间轴推进。

```text
跳到下一个关键断点
根据事件队列更新当前时间
生成周期性抽牌事件
生成周期性能量恢复事件
```

---

## 24.5 card_resolver.gd

负责卡牌效果结算。

```text
伤害
护盾
治疗
抽牌
延迟能量
范围伤害
```

---

## 24.6 enemy_ai.gd

负责敌方行动选择。

Demo v1 中可以很简单：

```text
选择固定普通攻击
选择一个合法目标
```

## 24.7 ui 模块

UI 只显示状态和接收玩家点击，不直接修改战斗逻辑。

所有战斗逻辑都应交给 battle_controller 和 card_resolver 处理。

# 25. Codex 开发要求

## 25.1 代码结构要求

Codex 开发时必须遵守：

```text
1. 不要把所有功能写进一个大脚本。
2. 战斗状态、事件队列、卡牌结算、敌方AI、UI显示必须拆分。
3. 卡牌和角色数据必须从 JSON 读取，不要硬编码在逻辑脚本中。
4. 中文文本放在 JSON 或独立数据文件中，避免硬编码到脚本里。
5. 文件编码统一使用 UTF-8。
6. 每个模块只负责自己的职责。
7. UI 不直接计算伤害，不直接修改生命和能量。
8. 所有数值变化都通过战斗逻辑模块处理。
```

# 26. Demo v1 验收标准

Demo v1 完成后，应满足以下标准。

## 26.1 战斗基础验收

```text
可以进入一场 4v4 战斗
我方和敌方都有生命显示
角色可以死亡
敌人全灭后胜利
我方全灭后失败
```

---

## 26.2 时间轴验收

```text
角色不会按固定回合行动，而是按行动时间行动
使用不同过载的卡牌后，下一次行动时间不同
速度更高的角色，实际过载更短
蓄力卡不会立即发动，而是在未来时间发动
```

---

## 26.3 卡牌验收

```text
打击能造成力量伤害
防御能提供意志护盾
迅捷打击过载短于打击
重击有蓄力且伤害更高
旋风斩能攻击所有敌人
迅捷防御能为单个我方角色提供护盾
群体防御能给所有我方角色护盾
治愈之光能恢复单个我方角色生命
群体治愈能恢复所有我方角色生命
战术抽取能抽2张牌
能量补给能在6时间后获得2能量
```

---

## 26.4 护盾验收

```text
护盾可以叠加
受到伤害时先扣护盾
护盾不足时再扣生命
角色行动前会清空自己的护盾
行动中获得的新护盾不会立刻清空
```

---

## 26.5 手牌与能量验收

```text
战斗开始抽5张牌
手牌上限为9
每5时间抽1张牌
手牌7时间后过期
能量上限为10
初始能量为3
每10时间恢复1能量
普通攻击恢复1能量
```

---

# 27. Demo v1 设计总结

Demo v1 的目标是验证：

```text
1. 时间轴战斗是否有趣
2. 蓄力和过载是否能形成决策
3. 共享手牌是否清晰
4. 能量系统是否能推动普通攻击和卡牌之间的选择
5. 护盾的时间窗口是否能让防御有策略性
6. 基础卡和通用卡是否能形成成长感
```

本 Demo 不追求完整游戏内容，而是优先把核心战斗规则做稳定、做清楚、做可扩展。

一句话概括：

> Demo v1 要完成的是一个可反复测试的 4v4 时间轴卡牌战斗原型。
