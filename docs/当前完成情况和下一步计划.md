# 当前完成情况和下一步计划

## 当前完成：阶段 1A、阶段 1B、阶段 1C 与阶段 2

已完成数据与核心模型基础：

- 角色、敌人、卡牌、初始牌组和战斗配置均已外置为 JSON。
- 正式名称与卡牌描述使用本地化 Key，并提供中文、英文 CSV。
- `GameDataLoader` 负责读取 JSON。
- `GameDatabase` 负责集中校验、建立单位与卡牌索引。
- `CardData` 负责保存卡牌定义与计算实际过载。
- `UnitState` 负责保存单位运行状态以及伤害、护盾、治疗规则。
- `BattleState` 负责保存单场战斗状态，并提供我方生命继承接口。

阶段 1B 已完成静态战斗界面：

- `battle_scene.tscn` 作为当前主场景，采用顶部时间轴、中部横向战场、底部卡牌区域布局。
- `timeline_panel.tscn` 与 `timeline_event.tscn` 独立负责顶部时间轴与行动事件标记展示。
- `unit_slot.tscn` 使用竖版立绘展示单位，并显示站位、名称、职业、生命条、护盾和行动时间。
- `card_view.tscn` 负责显示卡牌名称、描述、费用、蓄力和过载。
- 底部布局为抽牌堆、能量、手牌、弃牌堆。
- `BattleSetup` 集中创建初始展示状态与五张初始手牌。
- `BattleSceneController` 只负责连接状态和 UI，不计算战斗规则。
- 已设置 1280 × 720 窗口尺寸和战斗主场景。
- 已注册中英文 Translation 资源。
- 当前时间轴事件使用单位初始行动时间生成展示位置；阶段 2 接入真实事件队列后替换。
- 当前未实现战斗日志。
- 单位立绘已切换至 `res://image/` 下的透明 PNG，旧 `picture` 目录已删除。
- 占位时间轴事件在阶段 2 前均匀铺满时间轴，便于观察界面结构。
- 底部初始五张手牌已完整显示，并隐藏当前不需要的水平滚动条。
- 战场站位按 `我方4-3-2-1 | 敌方1-2-3-4` 展示，双方 1 号位最靠近中央。

阶段 1C 已完成基础玩家交互：

- `ActionRequest` 保存行动角色、行动类型、卡牌 ID 和目标 ID。
- `ActionValidator` 校验行动角色、卡牌费用、手牌持有情况与合法目标。
- `PlayerActionController` 管理普通攻击、卡牌、目标选择、取消与请求生成。
- `action_panel.tscn` 显示当前行动角色、普通攻击、选择状态和请求结果。
- 单位槽支持当前行动角色与合法目标高亮。
- 卡牌支持选择、能量不足禁用和单张卡牌副本高亮。
- 当前行动请求只生成、不执行；不会扣除能量、移除卡牌、改变生命或推进时间。

阶段 2 已完成事件队列与时间轴推进：

- `BattleEvent` 保存事件时间、类型、阵营、单位、卡牌、目标和创建顺序。
- `EventQueue` 负责稳定事件排序、同时间事件查询和死亡单位事件取消。
- `ActionScheduler` 将玩家请求转换为技能发动与下一次行动事件。
- `BattleResolver` 当前实现普通攻击、打击和防御的最小结算。
- `EnemyAI` 根据随机、最低生命和前排规则选择目标。
- `BattleFlow` 协调时间推进、同时间我方行动选择、敌方自动行动与技能结算。
- 我方四名角色首次行动时间均为 `0.0`；玩家可以自由选择同时间行动顺序。
- 敌方不再使用速度或过载，首次行动和后续行动均严格使用 `action_interval`。
- 敌方首次行动时间：潮汐蟹 `4.0`、裂隙虫与遗迹骷髅 `5.0`、藤蔓兽 `6.0`。
- 顶部时间轴已改为显示真实行动与技能事件。

## 已确认规则

- 所有单位首次行动时间为 `0.0`。
- 同时间、同优先级事件按创建顺序结算。
- Demo v1 每场战斗使用固定敌方阵容。
- 下一场战斗继承我方角色当前生命。
- 敌方生命、双方护盾、能量、手牌和事件等临时战斗状态在下一场战斗重置。
